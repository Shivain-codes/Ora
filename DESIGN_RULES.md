# STRICT FRONTEND DESIGN RULES — Ora (AskMongo) (standing directive from shivain, 2026-10-24)

## Core Instruction
Do NOT generate a generic, default, or typical AI-designed frontend. Every page,
section, layout, component, animation, and interaction must be intentionally
designed for a premium, distinctive, professional, visually exceptional result.

## 1. Approved Component Libraries (ONLY these)
- Aceternity UI — https://ui.aceternity.com
- Magic UI — https://magicui.design
- React Bits — https://reactbits.dev
- 21st.dev — https://21st.dev
- Motion Primitives — https://motion-primitives.com
- Origin UI — https://originui.com
- Animate UI — https://animate-ui.com
- Hover.dev — https://www.hover.dev
- Uiverse — https://uiverse.io
- shadcn/ui — https://ui.shadcn.com

Prioritize actual components from these libraries when technically compatible.
Never substitute generic AI components when a library component fits.

## 2. Approved Visual Inspiration
Awwwards, Godly, Land-book, Lapa Ninja, Mobbin, Refero.
Extract principles; do not copy whole sites.

## 3. Approved Animation & 3D
Spline, GSAP, Codrops, Rive.

## 4. Strictly Prohibited
Generic AI SaaS templates · default React/Tailwind layouts · repetitive rounded
cards · predictable 3-col feature grids · generic gradient heroes · purple/blue
AI gradients · random glowing backgrounds · excessive glassmorphism · generic
dashboards · floating decorations · decorative icons/emojis · repetitive layouts
· placeholder animations · uncustomized default components · generic type pairings
· inconsistent multi-library styling.

## 5. Mandatory Component Selection Process
1. Identify the section's purpose, UX, and visual requirements.
2. Search the approved libraries for suitable components.
3. Select the best fit for the visual identity.
4. Integrate + customize to the site's type, color, spacing, interaction language.
5. Ensure responsiveness, accessibility, performance.
6. Build custom ONLY when no approved component exists.
7. Never claim a library component without actually implementing it.
8. If a reference can't be accessed, state it — don't pretend.

## 6. Premium Standards
Exceptional hierarchy · sophisticated typography · consistent tokens · deliberate
whitespace · strong art direction · purposeful interactions · quality transitions
· unique-but-usable layouts · pixel attention · cohesive styling · fully responsive.

## 7. Technical Rules
Preserve framework/architecture · reusable components · official install methods ·
licensing respected · no needless deps · accessibility + reduced-motion ·
performance optimized · never sacrifice function for looks.

## 8. Final Quality Gate (verify before presenting)
Distinctive not AI-generated? · Components genuinely sourced? · Every section
purposeful? · Typography intentional? · Animations smooth/appropriate? ·
Identity consistent? · Premium on mobile + desktop? · Decorative effects removed?
If any NO → refine before calling it done.

## FINAL DIRECTIVE
DO NOT USE DEFAULT AI FRONTEND STYLE. Applies to ALL future frontend work in
this project unless explicitly overridden.
